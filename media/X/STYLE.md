# WKFLのX投稿の文体

この文書が答える問い: WKFLのXで、本人の普段の発言に近い文章をどう書くか。
対象: X @wkflstudio。更新: 2026-10-08。

## 投稿の前に

文案作成・修正・公開の前に毎回この文書と `../../playbooks/publishing.md` を読む。ユーザーが今回話した内容を起点にし、X上の過去投稿を実際に読んで口調の参考にする。
その文案を書くターンでファイルを開き、作業報告に参照先と反映する点を一言示す。原稿を書いた後にも、今回のフィードバックと実際の文章を照合する。

## 現在の指針

- Xに関する継続的な要望・文体の参照手順の拠点は `media/X/`。この文書に繰り返し役立つ指針を集約し、個別企画の原稿と調査は `drafts/`、公開結果は `posted/` に置く。会話の記録は、今後の判断に役立つ要点を選んで残す。
- 本人が使って感じたこと、疑問、試したことを、知り合いに話すくらいの普通の文章で書く。
- ユーザーの語彙と話の順序をできるだけ生かし、重複や音声入力の誤字を整える。
- 普通の語順で自然につながる文を書く。主語は文脈でわかる場合は省き、明示が必要なときの一人称は「僕は」。体験は何を使ってどうなったかで述べ、導入からその話題に入る。
- 語り口は日常の説明に合わせる。ドラマ的な場面演出、共感を演出する倒置・短文について、ユーザーから明確な不採用の指摘があった。
- 対象・出来事を具体的にし、関連する文を自然につなげる。段落は話題のまとまりで分ける。
- 結びは、その話で本人が思ったことや具体的な疑問にする。本人の立場と、調査で追加した事実を照合する。
- ユーザーの体験は本人が述べた範囲で書く。事実の裏付けが弱いところは、本人の疑問や仮説として表現する。
- 技術的な訂正は、その箇所を正確な言い方に直す。投稿全体のテーマと本人の関心を保つ。
- 本人独自の見立てと、そこからどう行動するかまでを書く。一般的な注意喚起より、本人が今回伝えたい具体的な主張を中心にする。
- 仮説は「〜だと思ってる」などで主張全体に位置づけ、普通の発言として通して書く。事実確認用のメモと公開本文の役割を分ける。
- 絵文字、感嘆符、くだけた表現は、その話題と元の発言の温度感に合わせる。
- まず1投稿に収め、説明が必要なら2投稿へ分ける。スレッド番号は読みやすさに役立つ場合に付ける。
- 最初の投稿は本文を優先し、出典URLは続きにまとめる。これはユーザーの配置の好みとして扱う。

ローカルには明示された要望と参照手順を残す。公開本文のサンプル集はXの投稿履歴を利用する。本人が修正した投稿を優先し、AIが作成して不採用になった文章は投稿記録として扱う。Xを読めなかった場合は、その事実を伝え、今回の本人の発言と保存済み要望をもとに作成する。
