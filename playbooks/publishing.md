# WKFLの記事・音声・動画をAIに投稿してもらう

この文書が答える問い: IDEで作った原稿をどう投稿するか。Chrome拡張とOS操作の違い、会社用・個人用の区別、下書きと公開の承認、VS Codeから利用できる範囲は何か。

対象: 個人プロジェクト WKFL。最終確認: 2026-10-08。

## 最初に読む運用方針

**制作はVS Code等のIDE、配信操作はChatGPTデスクトップアプリのCodexタスクで行う。** 同じMacの `/Users/kaya.matsumoto/projects/WKFL` を開き、保存済みファイルの絶対パスを渡せば引き継げる。会話履歴の共有を前提にせず、原稿・素材・投稿先・停止位置をファイルと依頼文で伝える。

デスクトップアプリでは、個人用Chromeのログイン状態を利用して入力・アップロード・公開操作を依頼できる。公開範囲はユーザーの依頼に従う。投稿先と目的が明確な通常の投稿で「投稿して」と依頼された場合は、文案作成から公開確認まで進める。「下書き」「ここで練習」の依頼は文案提示までとする。追加の確認が必要な操作は、その操作に適用される規則に従う。

## 操作する経路

| 経路 | 操作対象・認証 | WKFLでの位置づけ |
|---|---|---|
| Chrome拡張経由 | プロファイルごとのタブ、ページ内の入力欄・ボタン。既存のログインを利用 | 通常の投稿作業で優先する |
| OS経由のComputer Use | Macのアプリの画面・アクセシビリティ情報。対象ウィンドウのログインを利用 | ファイル選択など必要な場面で補助的に使う |
| 媒体のAPI・専用連携 | ブラウザを介さずサービスを操作。別途認証が必要 | 今回は設定・動作とも未検証。API連携は将来の別作業 |

MCPはツールを接続する仕組みで、その先でブラウザを操作する実装もAPIを呼ぶ実装もある。「MCP」という名称だけでは既存ログインを使えるか判断できない。

## 最初の接続設定

1. ChatGPTデスクトップアプリの設定 → Computer Use → Google Chromeから、公式ブラウザ拡張のストアページを開く。画面表記はアプリの版によって異なる。
2. **個人用Chromeプロファイル「夏弥」**でChatGPTブラウザ拡張をインストールし、接続を確認する。拡張機能はプロファイル単位で設定する。
3. 同じプロファイルで投稿先にログインする。追加認証が必要ならユーザーが対応する。
4. デスクトップアプリのタスクで `@Chrome` または対象タブを指定し、個人用プロファイルと媒体上のアカウントを照合してもらう。
5. ローカルファイルのアップロードで要求された場合、Chromeの拡張機能 → 詳細 →「ファイルのURLへのアクセスを許可する」を確認する。OS操作ではmacOSの画面収録・アクセシビリティ権限も必要になる。

会社用「職場」と個人用「夏弥」は、2026-09-27に別々の拡張接続として認識できた。接続IDやタブIDはその都度取得する。プロファイル名に加え、Xなら `@wkflstudio`、noteなら `wkflstudio`、Podcastなら対象番組を編集画面で確認する。名前が違う場合はアカウントの選択をユーザーに確認する。

## IDE・デスクトップ・Web版の違い

| 利用場所 | 確認できていること | 運用判断 |
|---|---|---|
| ChatGPTデスクトップアプリのCodex | このMacでOS経由のX入力、個人用・会社用Chrome拡張の接続を確認済み | 現在の配信操作の入口 |
| VS CodeのCodex拡張・CLI | 公式にMCP対応。同じCodexホストでMCP設定を共有する | 対応するブラウザ／OS操作ツールを別途接続し、実際に呼べることを確認すれば操作経路を持てる。今回の公式Chrome拡張・Computer UseがIDEでそのまま使えるかは未検証 |
| VS CodeのClaude Code | 2026-10-08、個人用「夏弥」にClaude拡張（https://claude.ai/chrome）を入れて接続し、note `wkflstudio`・X `@wkflstudio` のログイン状態で開けることを確認 | IDEから直接配信操作できる経路。拡張には**Claude Codeと同じclaude.aiアカウント（会社）**でログインする。Chromeプロファイルや媒体のログインとは別アカウントでよい。デスクトップ全体のComputer UseはVS Codeでは使えない |
| その他のIDEエージェント | 製品と導入ツールに依存 | 各エージェントの対応と接続先を確認する |
| 通常のWeb版チャット | ローカルCodex設定を直接読む構成とは異なる | Web画面を開いただけで、このMacのChrome接続を利用できるとは扱わない。利用可能な連携を別途確認する |

ブラウザ操作という技術自体がデスクトップアプリ専用という意味ではない。公式のブラウザ拡張・Computer Useの案内はデスクトップアプリを入口としており、**MCP設定の共有と、デスクトップ機能の利用可否は別々に確認する**。VS CodeのCodexでの操作テストは未実施。

## 制作から配信まで

Xの文案作成・修正・公開前には毎回 [Xの文体指針](../media/X/STYLE.md) を読む。文案を書く前にX @wkflstudio の過去投稿を数件読んで口調を参照する。担当を変える場合はこの文書と文体指針の絶対パス、元のユーザー発言、原稿、現在の依頼範囲を渡す。

1. IDEで既存の制作手順に従い、原稿・音声・動画を保存する。記事の正本は `articles/YYYY-MM-DD/`。X専用原稿は `media/X/drafts/` を利用できる。
2. 同じ日付ディレクトリに必要に応じて `publishing.md` を置き、媒体、原稿と添付のパス、タイトル、説明文、リンク、タグ、公開範囲、即時／予約とタイムゾーン、承認状況を記録する。認証情報は既存の秘密情報管理に置く。
3. デスクトップアプリに原稿と引き継ぎメモの絶対パスを渡す。別チェックアウトで作業した場合は、配信側が読める実ファイルの場所を明示する。
4. AIが対象アカウントを照合し、本文入力・素材添付・プレビュー確認まで進める。
5. 依頼された本文・添付・公開設定を照合する。公開を依頼済みの通常の投稿は公開へ進み、下書き依頼の場合は保存確認までで終了する。主張や投稿先が依頼から大きく変わる場合は、その変更をユーザーに確認する。
6. AIが公開操作を行い、投稿URLと表示内容を確認する。結果が不明なら既存投稿を確認してから次の操作を判断する。
7. `articles/YYYY-MM-DD/publishing.md` に結果・URL・時刻を記録する。Xは既存の `media/X/posted/` も利用でき、ログの置き場所を一つ選んで参照する。

> `/Users/kaya.matsumoto/projects/WKFL` の `playbooks/publishing.md` を読んでください。原稿は `/Users/kaya.matsumoto/projects/WKFL/articles/YYYY-MM-DD/articles.md` です。個人用Chrome「夏弥」のnote `wkflstudio` で下書きを作成し、保存結果を確認してください。今回は下書きまでです。

> `/Users/kaya.matsumoto/projects/WKFL/media/X/drafts/対象原稿.md` を個人用ChromeのX `@wkflstudio` に入力してください。本文と添付を確認できる状態まで進め、私の公開承認を待ってください。

日付・ファイル名は実在する対象に置き換える。承認を既に受けた具体的な投稿内容は引き継ぎ時に明示する。

## 2026-09-27の操作記録と注意点

- デスクトップアプリのComputer Useで、個人用Chrome「夏弥」のX `@wkflstudio` を認識し、テスト文を作成欄に入力した。公開操作は未実施。下書き保存の完了は未確認。
- OS経由の日本語入力・貼り付けで不安定さがあり、貼り付け時に元のクリップボードの別テキストが入った。直後に消去し、テスト文へ置き換えた。入力後は全文を照合する。
- アクセシビリティ情報と画面の表示に不一致があった。食い違った場合は操作を止めて状態を再取得し、必要ならユーザーに引き継ぐ。
- その後、ユーザーが個人用にも拡張を導入し、「夏弥」「職場」の2接続を確認した。接続確認と実際の投稿成功は別の検証段階。
